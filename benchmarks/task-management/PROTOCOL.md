# Protocol Phase 0 — task management, revision 9 (Codex Luna 6, weighted output cap)

Ngày chốt: 16/10/2026. Phạm vi quyết định: chất lượng task/state/context/checkpoint và hiệu quả một agent. Đây là protocol mới; không kế thừa các ngưỡng hoặc dữ liệu benchmark cũ. Không mở Phase 1 khi baseline chưa đạt 0.3.

## Lossless scope storage — candidate 27/10/2026

New independent operational freezes store the complete per-attempt ACL input once as `scope-input.json.gz`. Streaming gzip retains every entry, link, SID, workspace and executable allowlist; `scopeEnumeration` records compressed and decoded SHA-256, byte counts and entry count. The native evaluator decompresses the stream before running the same ACL policy and still accepts historical plain JSON. Corrupt compressed input fails closed. This changes storage only: no skipped paths, cached ACL decisions, shared mutable inventory, acceptance or schedule changes. Historical recovery JSON/JSONL artifacts and frozen protocols remain unchanged; new source/native proof and a new operational freeze are required before inference.

## G4 unblock candidate — 22/10/2026 (chưa freeze, không hồi tố)

Đối với **revision tương lai** đã vượt P0–P3 của `docs/phase8-2-g4-unblock-plan-20261022.md`, `providerObservations.scheme="ed25519-completed-command-v2"` thay thế policy chỉ ký startup-failure. Host ký **mọi** `item/completed` có `item.type="commandExecution"` và đầy đủ `id`, `command`, `aggregatedOutput`. Nếu là `unifiedExecStartup`, `status=failed`, `processId=null`, `exitCode!=0`, giữ nguyên wrapper `kind="provider-launch-failure",schemaVersion=1`. Các completed command khác dùng `kind="provider-completed-command",schemaVersion=2`. Sự kiện raw phải được ký nguyên `envelope={at,message}` và pin `binding={protocolHash,runId,threadId,turnId,attemptId,attempt}`. Event trùng ID, không thể ký, callback sau `turn/completed`, ghi/ACL thất bại đều chặn invocation (infrastructure_failed). Public key được pin; private key giữ ở host; thư mục signed observations trong agent workspace là read-only và mọi file được ghi exclusive.

Agent **tự viết** error ledger và canonical. Với lỗi direct exit nonzero, `outputReference={kind:"provider-completed-command",eventId,path,hash,failureMode:"nonzero"}`; với lỗi child bên trong completed event exit 0, dùng `failureMode:"reviewed-inner-error"` và host reviewer phải xác nhận lỗi thật từ raw. Loại startup tiếp tục `{kind:"provider-launch-failure",eventId,path,hash}`. `path` nằm trong `.handoff/provider-observations/`, `hash` là SHA-256 của signed JSON file; `entry.command` và output phải khớp nguyên command/output ký (hoặc outputMode artifact-reference với reference đầy đủ). Provider có thể trả `aggregatedOutput:null` cho completed command im lặng: giữ nguyên null trong chữ ký/raw, không thay bằng chuỗi rỗng hay bỏ field. Thành công im lặng không phải issue. Nếu command nonzero không có output, ledger dùng `outputMode:"artifact-reference"` với signed reference đầy đủ và mô tả rõ exitCode/null, không bịa stdout/stderr. Không coi completed event thành một process receipt. Mỗi error được đăng ký trong `.handoff/errors.json`, RESULT và canonical; lỗi nonzero không có issue tương ứng bị từ chối. Mọi event đã ký phải được so với raw và bound context trong host audit/review. Agent verifier kiểm signatures/file references có thể đọc nhưng host mới có raw retained trace để xác nhận semantic inner error và coverage.

Workflow chung B/S trong `comparison-attempts.mjs` làm tuần tự: bootstrap PowerShell nguyên vẹn trên **mỗi** shell/readback → task/session/source-before+predecessor → lease/edit/acceptance → signed events và ledger → manifests `{original,before,final,predecessor}` → source-claims với status/reason/files độc lập → RESULT và checkpoint → publish/canonical readback → verifier revision riêng → correction/republish/reverify khi lỗi. `predecessor=null` chỉ ở first task, về sau là source-after map của previous invocation kể cả chưa publish CURRENT. Không khai `rg-unavailable` nếu không có lệnh rg lỗi. Canonical phải tham chiếu claims, errors, acceptance, checkpoint và failure-report artifacts; RESULT/CURRENT có cùng compact serialized claims. Khi self-verifier FAIL thì giữ report bất biến và không được chốt hoàn tất. Agent vẫn quyết định sửa source/evidence; host chỉ ký event, kiểm raw, ghi audit và cleanup.

Khi provider đã hoàn tất và native stop chứng minh zero writers nhưng shell/bootstrap contract FAIL, record invocation mới có `status="terminal_infrastructure_failed"`, `measurementEligible=false`, `terminal={providerTurnStatus,nativeStopVerified,classification,reason,observedAt}`. Runner giữ `state.status="infrastructure_failed"`, raw/usage/calls, cleanup và quy tắc **no replay**. Trạng thái này không phải finished và không được mở review/rework/successor. Protocol cũ (`ed25519-provider-launch-v1`) tiếp tục được đọc bằng branch tương thích, không sửa raw/verdict cũ. G4 vẫn BLOCKED cho đến khi native proof, freeze, full B/S diagnostic và content review đủ.

## Revision 9 — weighted output cap 200k

Future freezes also permit a completed invocation record whose provider turn failed with `usageLimitExceeded` and `failureClass=provider_quota_exhausted` to receive BLOCKED review. This requires AppContainer writer stop, zero active processes, successful cleanup, and an audit containing only the expected final-turn usage rejection and optional workflow-history problems. Any other integrity failure remains disqualifying. PASS, REWORK, final PASS review and same-round successor remain forbidden for this path; usage and original failure evidence remain unchanged. Shared B/S instructions reconcile actual signed command exit codes instead of treating printed historical failures as new executions, and preserve every immutable FAIL report in corrective publications.

Subsequent independent freezes deliver the same mandatory B/S lifecycle, PowerShell bootstrap and evidence workflow through `thread/start.developerInstructions`, while retaining the current task as user input. The captured first startup instruction contains the complete bootstrapped PowerShell command, not a bare Node invocation. The runner retains exact developer instruction text and its SHA-256 before creating the thread. This changes instruction delivery for new diagnostics only; it does not remove bootstrap checks, authorize terminal-round replay, create additional model turns or change acceptance/content requirements.

Khôi phục ngày 19/10/2026 theo yêu cầu chạy lại baseline và 8.2: baseline frozen cũ và raw evidence đã mất. Cohort mới dùng B dựng riêng từ ZIP source-after-followup-20261011 cùng các thay đổi trước Phase 1 được phục hồi từ lịch sử phiên, build và freeze lại; không khẳng định byte-identical với revision 5 đã mất. `compare-run prepare --baseline-pointer <pointer>` nhận baseline mới, kiểm frozen inventory và bind pointer/manifest hashes cùng provenance. Các lượt B trong smoke/formal xen kẽ là dữ liệu baseline thu lại; không tái sử dụng kết quả lịch sử hoặc dùng candidate S làm B. Giữ cap, fixtures, acceptance, schedule, quality/review và efficiency thresholds hiện hành. Kết quả chỉ có hiệu lực với hai revisions mới đã freeze; không phục hồi hoặc chứng nhận lại các báo cáo lịch sử.

Theo yêu cầu ngày 19/10/2026, cap dùng tổng token có trọng số = uncached input + output × 8, với uncached input = inputTokens − cachedInputTokens. Manifest mới freeze `maxWeightedTokens=200000` và `outputTokenWeight=8`, áp dụng cùng công thức cho B/S. Dừng khi tổng có trọng số >200000; đúng 200000 vẫn trong cap. Giữ guard riêng 1000000 input+output, 10 phút và hai attempts. Reasoning là subset output, không cộng lần hai. Raw usage/accounting và metric input+output trong báo cáo hiệu quả không đổi. Đây là thay đổi policy cho round mới; phải freeze trước model calls. Không tính lại verdict hoặc sửa artifact các round cũ. Source này chưa chạy model.

### Captured lifecycle/context bootstrap — candidate 24/10/2026

For future independent freezes, each read-only lifecycle spec pins a separate context spec through `startupContext={path,hash}`. The shared capture helper validates that spec and its unused receipt ID before starting a task/session, captures the lifecycle command once, then actually executes and captures context startup. Both immutable receipt references appear in the same completed command output. Successful context output must bind to the task/session from the lifecycle stdout. Missing or altered specs, reserved context IDs and mismatched identities fail closed; lifecycle/context child failures and timeouts retain their real receipts and exits. Repeating the bootstrap never starts another task/session. After success, the agent reads both receipts and does not invoke context startup again. A context failure may be corrected only through a new captured context ID without restarting lifecycle. Direct uncaptured context remains insufficient for the workflow audit. Existing terminal rounds and their frozen helpers remain unchanged.

## Thu dữ liệu và xử lý retry

Host đặt attempt intent trước launch, gắn protocolHash/taskId/branch/repetition/stage/sessionId/runId/attemptId/sourceRevision/model/effort. Giữ prompt thực, raw provider events, stdout/stderr nguyên vẹn, source trước/sau, acceptance output, stop receipt, review verdict và timestamps UTC. Hash artifact khi hoàn tất; không đọc live DB đang có writer để làm bằng chứng bất biến.

Mỗi record cần `inputTokens`, `cachedInputTokens`, `cacheWriteInputTokens`, `outputTokens`, `reasoningOutputTokens`, elapsedMs, toolCalls, retries, rework, acceptance, handoffReview và failureClass. Thiếu trường provider hoặc instrumentation: null cùng lý do. Zero chỉ khi có phép đo/observed absence thật. `uncachedInput=input-cached` chỉ khi semantics xác nhận cached là subset của input và counters hợp lệ. Không cộng reasoning lần nữa vào output hoặc tool token vào tổng chưa rõ semantics. Cache-write provider không báo được phải null, dù adapter hiện có default 0.

Task limit revision 3 (lịch sử, policy revision 9 ở đầu tài liệu thay thế cho phép so sánh mới): tối đa 2 implementation attempts, 10 phút elapsed/attempt, 1000000 input+output tokens và 100000 uncached-input+output tokens/attempt; đo reasoning theo provider nhưng không cộng trùng. Qua ngưỡng: stop bằng acknowledged turn/interrupt, checkpoint bằng chứng/giả thuyết/next step, ghi failed/blocked. Một review sau attempt 1 dựa cùng rubric; chỉ được thêm một attempt rework nếu chưa đạt. Không sửa tests/acceptance hoặc bỏ failed attempt. Review bằng host đối chiếu diff/tests và checklist; reviewer model không thuộc B/S, nếu thêm phải revision protocol và cộng usage.

Infrastructure failure (provider không khởi động, raw usage mất, stop proof không đủ, recorder/evaluator lỗi) giữ slot và partial usage, dừng round để chẩn đoán. Không replay invocation đã launch với trạng thái không rõ; round mới phải có ID và accounting riêng. Product failure có đủ recorder/stop tiếp tục lịch, giữ source thật cho handoff; không xóa hoặc reseed để có PASS.

Wall time tính cả review/retry/handoff; báo thêm implementation-only riêng. Tool calls lấy completed call IDs trong raw trace, dedupe theo session+callId; dynamic Bridge calls và shell commands phân nhóm. Không đếm wrapper exec hai lần. Provider thiếu counters cache-write/reasoning được phép null; input/output/cached-input, elapsed, call trace, acceptance, source binding và actual model/effort là bắt buộc để tính hiệu quả token. Raw usage thiếu bắt buộc làm baseline incomplete, không thay bằng context estimate.

## Rubric chất lượng và ngưỡng quyết định

Mỗi task cần PASS toàn bộ fixed acceptance, đúng allowed diff, không sửa read-only inputs, không dependency ngoài scope. RESULT.md ghi đúng lệnh/kết quả/giới hạn, không claim test chưa chạy. Release S cần đủ 5 repetition: 20/20 task outcomes mỗi nhánh PASS (handoff chain tính một task, hai invocations), không mất binding/state/constraints, không duplicate ownership hoặc ghi đè source khác. Báo cả first-attempt pass rate và retry-inclusive pass rate. Một lỗi integrity chặn release dù median tốt.

Ngưỡng mới của protocol này: median paired total-token ratio S/B ≤0.90 trên 15 task độc lập; median uncached-input ratio ≤1.00; median wall-time ratio ≤1.10; output-token ratio ≤1.10. Handoff báo riêng trên năm chain: median total-token ratio ≤1.00 và 5/5 continuity reviews PASS. Tính mỗi task gồm tất cả attempts/rework/review/Bridge bookkeeping có usage; không chỉ compile tokens. Ratio mẫu thiếu hoặc mẫu B=0 giữ null và không bỏ mẫu khỏi denominator để đạt gate. Không áp ngưỡng chính xác nếu mandatory usage thiếu.

Báo median, min/max, p95 nearest-rank (rank=ceil(0.95*n)), từng pair, aggregate sums và mọi trường hợp xấu đi, phân tách infrastructure/product failure. Năm repetition chỉ là gate pilot, không khẳng định ý nghĩa thống kê hoặc tổng quát hóa cho mọi task.

Chi phí tiền = uncachedInput*rateUncached + cachedInput*rateCached + cacheWrite*rateWrite + output*rateOutput, quy đổi về cùng đơn vị triệu token, chỉ dùng khi xác nhận các nhóm không chồng lặp. Pricing record phải có URL nguồn chính thức, model exact, currency, effective/retrieved date và semantics từng nhóm. Hiện chưa thu pricing: mọi monetary cost=null; không suy subscription quota thành giá bằng 0 và không kết luận tiết kiệm tiền. Thiếu pricing không chặn token pilot nhưng chặn claim về tiền.

# G4 lifecycle and verification history

First-task startup runs `task start` exactly once and reuses the initial session it creates. Read task/session IDs from captured stdout before context startup, leases or checkpoint. Do not also run `session start`. A subsequent prompt in an active session reuses that session. Reviewed rework and handoff stage 2 retain the same task/workspace and open one fresh session after native stop and predecessor session closure. Host review checks immutable captured startup receipts, including sessions already closed at cleanup. A lifecycle violation requires BLOCKED and cannot authorize same-round rework or a successor.

Every FAIL verification report created in the current invocation and valid same-task/workspace ancestor chain must remain an immutable JSON file under `.handoff/verifications/`, with a unique revision and a direct canonical artifact reference. Signed observations and error ledger entries do not replace the report. Host validation binds captured verifier stdout to raw command receipts and report SHA-256; ancestor snapshots preserve requirements even when a later invocation deletes a file. Foreign branches and sibling chains are excluded. Missing files, changed bytes, duplicate revisions and escaped paths fail closed.

The self-verifier checks reports existing before its invocation and then exclusively writes a fresh report. After FAIL, correct and republish with that new FAIL report retained before verifying another revision. A final PASS binds the publication it checked and does not require a reference to its own hash. A changed canonical publication requires another verification revision. An empty error ledger with no FAIL reports remains valid. Self-verification does not establish authoritative raw history or native boundary proof; these remain host gates.
